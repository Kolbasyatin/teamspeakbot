# Источники данных по серверам Arma Reforger

Рабочий файл для разбора вопроса: **откуда брать длину очереди на вход** и что ещё можно получить
помимо того, что отдаёт A2S. Не решение, а собранный контекст — чтобы завтра начать не с нуля.

Проверено 2026-08-02. Всё, что ниже, разделено на «проверил руками», «вывод» и «не проверено» —
граница важна, потому что часть выводов сделана по форме ответа, а не по документации.

## 1. Зачем это нужно

Длина очереди — фича из `PLAN.md`, раздел «F. Фичи». A2S её не отдаёт: протокол знает имя, карту,
число игроков, ботов и теги, и всё. Значит нужен второй источник.

### Жёсткое требование: чужие серверы

**Мониторим серверы, которыми не владеем.** Источник обязан отдавать данные по произвольному
серверу, без участия его хозяина: ни поставить туда мод, ни попросить включить API, ни получить
доступ к его машине мы не можем.

Это отсекает целый класс решений сразу — всё, что требует что-то поставить или настроить **на
самом игровом сервере**. Остаётся ровно три пути:

1. централизованный источник Bohemia (первоисточник, если он публичен);
2. сторонние агрегаторы, которые этот источник зеркалят (armahq и другие);
3. **сама игра** — её браузер серверов уже показывает весь список с очередью, значит клиент
   к этим данным доступ имеет. По сути тот же первоисточник, но добытый через игру.

Всё остальное годится только для своих серверов — то есть не годится.

Инфраструктура под это уже готова (итерации от 2026-08-01):

- у сервера может быть несколько источников (`server_query_sources`);
- главный определяет `online`/`offline`, второстепенные только дополняют данные;
- отказ второстепенного не влияет на статус и не растит `failedChecks`;
- `rest`-источник разбирается по карте полей из конфига, включая вложенные пути (`data.joinQueue.size`);
- слияние сводит ответы по приоритету.

**Чтобы завести источник с очередью, нужно:** поле `queueLength` в `ServerQueryResult`, строка
в `SERVER_QUERY_FIELDS` (компилятор потребует сам), строка в `server_query_sources` с картой.
Кода писать не придётся — если источник отдаёт JSON по HTTP.

## 2. armahq.com — проверено

### Кто это

**Сторонний ресурс, не Bohemia.** В подвале сайта прямым текстом: `Not affiliated with Bohemia
Interactive`.

> Заголовок `### Bohemia server list get` в `sinusbot.http:32` вводит в заблуждение — поправить.

### Данные, которые он отдаёт

`GET https://www.armahq.com/api/servers/full` — HTTP 200, **29 МБ**, 5109 серверов, без авторизации.

Поля одного сервера:

```
id, name, mods[], flags, region, updated, visible, battlEye, favorite, hostType,
joinable, official, sessionId, pingSiteId, scenarioId, gameVersion, hostAddress,
playerCount, platformName, runtimeStats, scenarioName, directJoinCode,
detailsUpdatedAt, playerCountLimit, passwordProtected, hostedScenarioModId,
supportedGameClientTypes, joinQueue, lastJoinedAt
```

### Очередь есть и она живая

```json
"joinQueue": {"size": 0, "type": "REGULAR", "maxSize": 20, "positionAvgWaitTime": 47}
```

- присутствует у **1778 серверов из 5109** — то есть поле опциональное, отсутствие надо переживать
  (наша модель это уже умеет: все поля `ServerQueryResult` необязательные);
- на момент снимка у **115 серверов** очередь была непустой, максимум — **50 человек при 128/128**;
- `runtimeStats` пуст у **всех** 5109 серверов — тупик, на него не рассчитывать.

### Наш сервер в выдаче есть

UUID `4fc5ae8e-de88-483d-babc-7c3e7837b577` из `sinusbot.http:36`:

```
name             = [RU] #1 | RUBEZH | RUSSIAN SERVER | RUBEZH-ARMA.RU
hostAddress      = 178.72.143.132:2001
playerCount      = 119 / 128
joinQueue        = {size: 0, type: REGULAR, maxSize: 20, positionAvgWaitTime: 47}
region           = EU
official         = false
hostType         = CommunityDs
```

### Главная проблема — доступ

| Запрос | Результат |
|---|---|
| `GET /api/servers/full` | HTTP 200, 29 МБ, весь список |
| `GET /api/servers?id=<uuid>` | HTTP 400 `{"error":"Access token is required"}` |

Посерверного запроса без токена нет. Качать 29 МБ на каждом тике опроса нельзя — при интервале
5 секунд это ~500 ГБ в сутки только на один сервер.

Сайт за Cloudflare: обычный fetch получает 403, `curl` с браузерным `User-Agent` проходит.
Лимиты на запросы неизвестны.

## 3. Откуда armahq берёт данные — это вывод, не факт

Своего заявления с их стороны я не нашёл. Но в выдаче есть поля, которые **через A2S получить
нельзя в принципе**:

```
sessionId, directJoinCode, pingSiteId, hostType: "CommunityDs", official: false,
supportedGameClientTypes: [PLATFORM_PC, PLATFORM_XBL, PLATFORM_PSN],
mods: [{modId: "5EB139459EBF5C16", version: "1.0.64"}], joinQueue
```

Код прямого подключения, идентификаторы модов из Workshop, состав очереди — это понятия бэкенда
Bohemia, а не игрового протокола. Два штампа времени (`updated`, `detailsUpdatedAt`) намекают
на кэш поверх чужого источника.

**Вывод:** armahq почти наверняка зеркалит официальный бэкенд Bohemia — тот же, что кормит
внутриигровой браузер серверов. Если это так, то данные в принципе доступны и напрямую, минуя
посредника. Это и есть главная гипотеза на завтра.

## 4. Что проверить завтра

### 4.1. Официальный источник Bohemia

Гипотеза из п. 3 говорит, что искать надо тут. Не проверено ничего.

- `community.bistudio.com/wiki/Arma_Reforger:REST_API_Usage` — страница существует, содержимое
  не читал (отдала 403 на fetch, надо смотреть в браузере). По названию — самое перспективное.
  Важно понять: это API **игрового сервера** для его же владельца или централизованный API Bohemia?
- `community.bistudio.com/wiki/Arma_Reforger:Server_Management`, `:Server_Config`, `:Server_Hosting`
  — та же серия страниц.
- В одном из результатов поиска упоминался веб-браузер серверов на `master.bistudio.com`.
  **Не подтверждено**, проверить существование.
- Если официальный список отдаётся публично — это лучший вариант: первоисточник, без посредника.

### 4.2. Другие агрегаторы

Раз нужен охват произвольных серверов, armahq — не единственный кандидат, и завязываться на один
источник незачем. Всплывали в поиске, **ни один не проверен**:

- `battlemetrics.com/servers/reforger` — крупнейший, у BattleMetrics есть документированный API
  с ключами. Смотреть первым: если у них есть очередь, это самый предсказуемый вариант из сторонних.
- `gamemonitoring.net/arma-reforger/servers`
- `gs4u.net/en/armareforger/`
- `play-servers.com/armareforger`
- `top-games.net/arma-reforger`

По каждому один и тот же список вопросов: есть ли публичный API, отдаёт ли очередь, нужен ли ключ,
какие лимиты, можно ли запросить один сервер (а не весь список).

### 4.3. Игра как источник — идея zalex

Формулировка zalex: **в самой игре я открываю браузер серверов и вижу там все серверы, очередь
и всё остальное, что мне нужно. Значит мод может работать как клиент этого браузера, а я буду его
опрашивать.**

Это не мод на игровом сервере (такой пришлось бы ставить чужим людям, и вариант отпадал бы сразу),
а мод или клиент **на нашей стороне**, читающий список серверов так же, как это делает игра.

Чем идея сильна:

- **Требование «чужие серверы» выполняется полностью.** Браузер видит все серверы, ничьего согласия
  на это не нужно — он для того и сделан.
- **Это первоисточник, а не зеркало.** Если гипотеза из §3 верна и armahq зеркалит бэкенд Bohemia,
  то браузер игры берёт данные оттуда же — только без посредника, без его лимитов, токенов и 29 МБ.
- **Данных заведомо не меньше**, чем у агрегаторов: они показывают ровно то, что видит игрок.

Что надо выяснить:

- **Есть ли у Enfusion Script API доступ к списку серверов?** Ключевой вопрос: мод — это скрипты
  внутри игры, и вопрос в том, открыт ли ему браузер серверов как данные, или это закрытая часть UI.
  Смотреть в script API в BIKI.
- **Как отдавать наружу?** Мод должен как-то доставить данные нашему демону: HTTP-запрос из мода,
  файл на диске, что-то ещё. Зависит от того, что Enfusion разрешает скриптам.
- **Можно ли запустить это без человека и без монитора?** Клиент Reforger — полноценная игра
  с рендером. Нужен ли GPU, переживёт ли headless-режим, можно ли держать процесс сутками.
  Отсюда же вырастала мысль про серверный дистрибутив: он легче — но умеет ли он читать браузер
  серверов, большой вопрос, скорее всего это чисто клиентская функция.
- **Правила Bohemia.** Автоматизированный клиент, постоянно висящий на списке серверов, — надо
  понять, не считается ли это злоупотреблением.

Оценка: самая перспективная идея из «своих» и самая дорогая в проверке. Разумный порядок — сначала
§4.1 (вдруг официальный список публичен и всё это не нужно), потом §4.2, и только потом сюда.

### 4.4. Токен armahq

Запасной путь: написать владельцам, попросить токен для посерверного запроса. Оставляет чужую
зависимость, но снимает проблему 29 МБ.

### 4.5. Про rubezh-arma.ru — не наш сервер

`GET https://rubezh-arma.ru/api-server-info.php?server=3` лежит в `sinusbot.http:40` и **не является
нашим API**: серверы у нас теперь другие. Как источник не рассматривается — это API конкретного
чужого сервера, оно не масштабируется ни на кого, кроме него.

Единственная возможная польза: посмотреть, что вообще принято отдавать в таких самописных API —
но это любопытство, а не путь к решению.

## 5. Ограничение, которое верно при любом исходе

Сторонний агрегатор без SLA годится **только во второстепенные источники**. Статус `online`/`offline`
берём у A2S, очередь — у второго источника. Если armahq (или что там будет) ляжет, сервер не должен
уезжать в `offline`.

Это ровно то, что уже построено: `role = primary` у A2S, `secondary` у источника данных, отказ
второстепенного логируется и на статус не влияет. Менять архитектуру ни под один из вариантов выше
не придётся.

Раз серверы чужие, это ограничение не смягчится никогда: **любой источник очереди будет внешним
и ненадёжным по определению**, потому что мы не контролируем ни его, ни сами серверы. Главным
источником останется A2S — он хотя бы отвечает напрямую от игрового сервера.

Отсюда же следует, что источников очереди со временем может стать несколько (armahq + battlemetrics
+ что найдётся) — как страховка друг от друга. Приоритет решит, чьё значение победит, а молчание
любого из них ничего не сломает. Модель это уже поддерживает без единой правки.

## 6. Как воспроизвести проверки

```bash
# полный список (29 МБ, без авторизации)
curl -sS -A "Mozilla/5.0" 'https://www.armahq.com/api/servers/full' -o armahq.json

# наш сервер в выдаче
python3 -c "
import json
d = json.load(open('armahq.json'))
s = next(x for x in d['servers'] if x['id'] == '4fc5ae8e-de88-483d-babc-7c3e7837b577')
print(json.dumps(s, ensure_ascii=False, indent=2))"

# посерверный запрос — требует токен
curl -sS -A "Mozilla/5.0" 'https://www.armahq.com/api/servers?id=4fc5ae8e-de88-483d-babc-7c3e7837b577'
# {"error":"Access token is required"}
```

Пример сервера взят из выдачи как первый попавшийся с непустой очередью — свои серверы для проверок
не нужны, у armahq в списке все.
